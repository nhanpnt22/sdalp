1. Abstract
==================================================
H-SDACLP defines a protocol for orchestrating software development agents in a continuous, closed-loop lifecycle. It enforces strict separation of concerns across lifecycle execution, data modeling, storage, observability, and governance, ensuring a fully auditable, reproducible, and human-in-the-loop system.

4. Global Invariants (Cross-Cutting)
==================================================

CVersion:
- ALL artifacts MUST be versioned
- Append-only
- Full lineage traceable

CRevision:
- ALL changes MUST be revision-tracked
- MUST include actor, timestamp, diff
- Full history reconstructable

==================================================
5. Design Principles (Control Layer)
==================================================

HITL:
- Human-required: CMS, CAD, CA
- Human accountability enforced

SoC:
- One phase = one agent
- No shared state
- No cross-phase mutation

RACI:
- Every phase MUST define R/A/C/I

C<name> (Extensibility Model):
- Each C<name> MUST define:
  doc / spec / RFC / agent / environment / deployment / development / definition
- MAY evolve per application
- MUST comply with core invariants

MA (Minimal Adoption):
- Subset adoption allowed
- MUST preserve core invariants

16. Definition
==================================================

H-SDACLP (SDALP) is a SoC-enforced, RACI-governed, fully versioned and revision-tracked, human-in-the-loop protocol that structures software development as a continuous lifecycle across execution, data, storage, observability, and governance layers, ensuring auditability, reproducibility, and controlled decision-making.
